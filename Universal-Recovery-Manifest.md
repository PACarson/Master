# Universal Recovery Manifest

Ecosystem-level checkpoint ledger, required by `Universal_Engineering_Framework_v1_12.md` §0.6 item 4 (Checkpoint hierarchy). Complements — does not replace — each project's own `00_Project_State.js` (§0.2), which is where a single project's own file/Engine/Sprint checkpoints get recorded. This file exists specifically for work spanning more than one project/OS, or more than one AI session: exactly the shape of the Universal Governance Propagation task that created it.

**This is the authoritative record of what has actually been persisted and verified.** If a session is interrupted, the next session resumes from the latest row here — not from memory of what the prior session intended to do (UEF §0.6 item 4; Part 13 Stop Conditions of the task that produced this file).

## How to read this table

- **Checkpoint Level** — `FILE` (one file, individually persisted+verified) · `ENGINE` (every file in a multi-file Engine cleared) · `SPRINT` (every Engine in a Sprint cleared) · `GOVERNANCE` (a governance rule itself is now canonically defined) · `STATUS` (a status/registry document now truthfully reflects reality). This task's own units are individual governance files, not code Engines/Sprints — so its rows are almost entirely `FILE`, with `GOVERNANCE`/`STATUS` milestone rows layered on top where a meaningful threshold is crossed.
- **Status** — `Persisted+Verified` (write confirmed readable back — the only state that should remain at rest) · `Persisted, unverified` (written, read-back not yet done) · `In progress`.
- **Source-of-Truth Status** — `Authoritative` (this is the current canonical copy) · `Historical` (superseded, kept for provenance) · `Draft`.
- Rows are append-only, same as this ecosystem's Event Contracts (UEF §3) — a correction is a new row, not an edit to an old one.
